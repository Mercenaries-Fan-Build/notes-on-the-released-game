# Runtime Lua Binding Enumeration (lua_enum.asi)

> **Purpose:** Produce a definitive inventory of Mercenaries 2 Lua engine bindings by
> walking the live global table with `lua_next()` and by scanning `luaL_Reg` tables in
> `.rdata`. Complements the static audit in [`lua_engine_bindings_audit.md`](lua_engine_bindings_audit.md).

---

## Overview

`lua_enum.asi` is a 32-bit Windows ASI plugin (same loader stack as `dlc_enable.asi`):

1. **Captures `lua_State*`** — redirects `Sys.IsDemoMode` / `Sys.GetLanguage` registration
   entries to a one-shot wrapper that records `L` then chains to the original C function.
2. **Resolves Lua 5.1 C API** — scans the cracked retail EXE `.text` / `.rdata` for known
   string xrefs (`invalid key to 'next'`, `LUA_GLOBALSINDEX`, etc.) to locate `lua_next`,
   `lua_getfield`, `lua_type`, `lua_settop`, and related helpers.
3. **Runtime walk** — after ~10 seconds, iterates `_G` with `lua_next(L, LUA_GLOBALSINDEX)`,
   recursing into subtables up to depth 4 with a visited-table set to avoid cycles.
4. **Static walk** — scans the known registration cluster (`0x00B98770`–`0x00B99200`) and
   namespace `luaL_Reg` tables (Sys, Net, Object, …) for `{name, func}` pairs.
5. **Writes output** next to the ASI in `scripts/`:
   - `lua_bindings_runtime.txt`
   - `lua_bindings_runtime.json`
   - `lua_enum.log` (diagnostics)

Enumeration runs on a **worker thread** inside `__try/__except` blocks so failures log and
return without crashing the game.

## Build

From the repo root:

```bash
make lua-enum-asi OUTPUT=./output
```

Or directly:

```bash
make -C tools/lua_enum_asi mingw
```

Debug build (MessageBox on `DllMain` attach — do not ship):

```bash
make -C tools/lua_enum_asi mingw-debug
# or
make lua-enum-asi-debug OUTPUT=./output
```

## Deploy

1. Copy `lua_enum.asi` to `<Mercenaries 2>/scripts/lua_enum.asi`.
2. Ensure ASI Loader is installed (`dinput8.dll` + `scripts/` folder).
3. Launch the game normally (main menu or in-game is fine).
4. Wait **at least 12–15 seconds** after the process starts (plugin sleeps 10s, then scans).
5. Quit the game (optional — files are written before you quit).
6. Collect from `<game>/scripts/`:
   - `lua_bindings_runtime.txt`
   - `lua_bindings_runtime.json`
   - `lua_enum.log`

## Output format

### Text (`lua_bindings_runtime.txt`)

```text
# Mercenaries 2 Lua bindings (runtime inventory)
# Generated by lua_enum.asi
# local_time=2026-05-19 14:32:01
# lua_state=0x12345678
# runtime_walk=yes
# binding_count=842
# Columns: path | type | func_va | depth | source

Sys.LoadAsset | function | 0x005E1234 | depth=0 | runtime
Sys | table | 0x00000000 | depth=0 | runtime
Net.IsMultiplayer | function | 0x005F5678 | depth=0 | static
...
```

| Column | Meaning |
|--------|---------|
| `path` | Dot path (`Sys.LoadAsset`, `Net.IsMultiplayer`, …) |
| `type` | Lua type at enumeration time (`function`, `table`, `number`, …) |
| `func_va` | C function pointer for `function` values; `0` if unknown / non-CFunction |
| `depth` | Nesting depth from `_G` (0 = global or static flat name) |
| `source` | `runtime` = live `lua_next` snapshot; `static` = `.rdata` `luaL_Reg` scan |

### JSON (`lua_bindings_runtime.json`)

```json
{
  "generator": "lua_enum.asi",
  "lua_state": "0x12345678",
  "runtime_walk": true,
  "binding_count": 842,
  "bindings": [
    {
      "path": "Sys.LoadAsset",
      "type": "function",
      "lua_type": 6,
      "func_va": "0x005E1234",
      "depth": 0,
      "source": "runtime"
    }
  ]
}
```

`lua_type` uses Lua 5.1 constants (`0=nil`, `6=function`, `5=table`, …).

## Limitations

| Limitation | Detail |
|------------|--------|
| **Snapshot in time** | Only bindings present when enumeration runs (~10s after load). Late-registered or dynamically removed entries may be missing. |
| **`lua_State*` capture** | Requires a `Sys.*` call before enumeration. If capture fails, static `.rdata` results are still written; runtime section is skipped. |
| **API resolution heuristics** | Lua is statically linked; C API addresses are found by pattern/string scan. A different EXE build may need updated signatures. |
| **Depth cap** | Subtables deeper than 4 levels are not recursed. |
| **Metatables / userdata** | Userdata methods and metatable entries are not expanded. |
| **C vs Lua functions** | `func_va` is only set when `lua_tocfunction` recognizes a C closure; Lua closures show `0x00000000`. |
| **Static scan overlap** | Static entries list registration-time C bindings; runtime entries reflect live table contents (may include Lua tables mirroring namespaces). |

## Troubleshooting

| Symptom | Check |
|---------|-------|
| No output files | `lua_enum.log` — ASI not loaded? Verify `dinput8.dll` / `scripts/` path. |
| `runtime_walk=no` | `lua_state=0x00000000` in log — play past initial shell or wait in menu longer; ensure cracked EXE layout. |
| Empty `binding_count` | Exception during scan — see log; may indicate API resolution failure on this EXE build. |
| Very low static count | Wrong EXE variant — registration VA cluster must match cracked retail layout. |
