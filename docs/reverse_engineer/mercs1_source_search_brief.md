## 0. The one-paragraph problem

Mercenaries 2 (Pandemic, 2008) stores every model's skeleton/scene-graph node names **only as 32-bit
hashes**. The name strings were stripped from the shipped data. We have enumerated all 10,199 distinct
node hashes and recovered ~4,700 names by reconstructing the studio's naming grammars. The remaining
~5,500 are blocked on **vocabulary**: we can prove (by hash-state algebra) exactly what structure a
name has, but we cannot spell the words, because those words do not appear anywhere in the shipped
game's string tables.

Mercenaries 1 (*Playground of Destruction*, 2005) is the same studio and the direct engine ancestor.
Its **source code** should contain the very things we lack: the exporter that *generates* these node
names, the naming constants, and the hash function itself.

**You do not need to understand our tooling. You need to find strings and code. Everything below is
a concrete search list, ranked by value.**

## 1. The hash function — verify it, then you can self-check every hit

This is Mercs 2's node/asset hash. If Mercs 1's source contains this function (likely named something
like `Hash`, `StringHash`, `MakeHash`, `HashName`, `CRC`, `Checksum`, `PgHash`, `NameToId`), **that is
itself a major find — send it verbatim, including any variants.**

```python
FNV_OFFSET = 0x811C9DC5
FNV_PRIME  = 0x01000193
MASK       = 0xFFFFFFFF

def pandemic_hash_m2(text: str) -> int:
    """FNV-1a variant: per-byte lowercase fold (b | 0x20), then a 0x2A finalize."""
    data = text.encode("ascii")
    if not data:
        return 0
    h = FNV_OFFSET
    for b in data:
        h ^= (b | 0x20)          # <-- case-insensitive fold
        h = (h * FNV_PRIME) & MASK
    h ^= 0x2A                    # <-- finalize
    h = (h * FNV_PRIME) & MASK
    return h

# sanity: pandemic_hash_m2("piece1a") == 0x39422307 ... (any string works; the point is to compare
# against whatever hash function Mercs 1 uses. If they match, EVERY string literal in the Mercs 1
# source becomes a candidate we can test instantly.)
```

**Key properties we rely on (and that you can exploit locally):**
- It is **case-insensitive** (`b | 0x20`), so `Slice2A` and `slice2a` hash identically. Casing in the
  source tells us nothing, and you should not filter on it.
- It is **invertible** (the multiplier is odd), which is how we recover interior "states" — see §5.

**If the Mercs 1 hash differs** (different offset/prime/finalize, or a plain CRC32), that is still
extremely useful — send the exact function. It tells us when and how the scheme changed.

## 4. ★ THE FOUR SPECIFIC OPEN QUESTIONS

These are what we actually need. Even a partial answer to any one is worth hundreds of names.

### Q1 — What hangs *underneath* a wheel bone? (~670 nodes blocked)
In Mercs 2, every vehicle wheel bone (`bone_wheel_fl`, `bone_wheel_rr`, …) has **exactly 3 unnamed
child nodes**. We have proven by geometry they are **not** dual tires and **not** axles (they sit on
the model centreline, all three the same size as the wheel). They look like **LOD variants or mesh
sub-parts**. They carry **no side token** and **no index** — each is individually named.

> **Find:** what does a Pandemic exporter call the mesh/geometry children of a wheel? Look for
> `tire`, `tyre`, `rim`, `hub`, `tread`, `lod0/lod1/lod2`, `_lo/_med/_hi`, `_mesh`, `_geo`,
> `_render`, `_col`, `_collision`, `_shadow`, `_blur`, `_deform`, `_skin`, or an LOD-suffix constant.

### Q2 — The universal vehicle destruction group node (present in 172 vehicle models)
Three nodes appear in nearly every vehicle, forming a destruction switch:
```
<STEM>            (the SWIT group node; parent is `bone_frame`)
<STEM>_pristine   (the intact branch: holds hp_seat_*, hp_dock_*, bone_hub_*, …)
<STEM>_ruin       (the destroyed branch)
```
We have **proven** they share a stem and recovered the stem's exact hash state. We have **exhaustively
ruled out** every string of ≤8 chars over `[a-z_]`, every single word in the game's own 648k-token
string corpus, and every 2-word compound of game vocabulary. **The stem is ≥9 characters and is a word
the shipped game never spells.**

> **Find:** what does Pandemic call the top-level destructible-body group on a vehicle?
> Candidates to grep: `damagegroup`, `damagemodel`, `destructiongroup`, `bodygroup`, `vehiclebody`,
> `destructible`, `breakgroup`, `swapgroup`, `stategroup`, `lodgroup`, `hierarchyroot`…
> **Or just send us any long identifier that sits between a vehicle's frame and its pristine/ruin
> branches.** We can hash-test hundreds of candidates in a second.

### Q3 — The per-model debris series stems
Buildings shatter into `piece1a_propdebris00..95` (we cracked that). But ~1,478 *other* debris nodes
belong to series whose stem word we cannot spell. They live under `piece*_pristine` and in specific
models (e.g. a large park).

> **Find:** any other `<something><NN>` debris/detail/prop naming used by the destruction or
> set-dressing exporter. Look near `propdebris` / `propattach` for sibling constants.

### Q4 — The last ~15 human-rig bones
The Mercs 2 biped rig is ~99 bones; we have all but ~15. The missing ones sit at known positions in
the skeleton (between Spine2 and Chest; parent of the jaw; a 4-bone midline face chain that looks
tongue-like; a bone between LShoulder and LBicep; an accessory tail after `bone_hair`). Known
siblings: `bone_lbicep`, `bone_lforearmroll`, `bone_lthumb1`, `bone_chestleft`, `bone_attach_hipright`,
`bone_ub`, `bone_lb`, `GlobalSRT`.

> **Find:** the character rig's canonical bone list, any biped-export bone-name table, or the FaceFX
> bone list. **Note:** we have *proved* that two of these (the pair heading the left/right leg chains)
> are **not** a glued `l`/`r` pair — so do not assume every pair is mirrored.

## 6. What "send back" should look like

For each finding, give us:
1. **The file path** in the Mercs 1 tree.
2. **The verbatim code or string** (do not paraphrase, do not fix casing — casing is irrelevant but
   spelling and underscores are everything).
3. **Surrounding context** (the enclosing function, the array it sits in, adjacent constants).

Even a *negative* is valuable: "the exporter builds names as `<mesh>_<lod>` and there is no debris

`sprintf`/`strcat` that assembles a node name from parts. That one file could unblock several thousand
names at once.
