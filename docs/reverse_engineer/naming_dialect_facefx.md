# The FaceFX facial-bone naming dialect — Mercenaries 2

**Purpose.** A rigorous artifact of the *naming patterns and vocabulary* of Mercs2's facial rig, so that
the 8 unnamed head/jaw/mouth-region tracks (25, 26, 28–33 of the 105-bone reference clip) can be attacked
with a human-templated generator (`tools/bone_forge.py`) instead of blind brute force. Names survive only
as `pandemic_hash_m2(name)` — a **case-insensitive** 32-bit FNV-1a variant — so a lone hash match is *not*
proof. This document is about **which strings are plausible**, graded, not about claiming cracks.

Companion: [`bone_census.md`](bone_census.md) (whole investigation), [`../data/human_rig_reference_105.txt`](../data/human_rig_reference_105.txt)
(track order that pins the unknowns anatomically).

---

## 1. Structural grammar

The facial rig is one contiguous block of the shared biped, tracks **25–52** of clip `0x60894D81`,
nested under `Bone_Head` (track 24). Twenty of these are confirmed by shipped strings
(`output/block_strings.txt`, the `facefxactor` c3 blocks). Their grammar:

```
bone_<feature>[_<position>]_<side>
```

* **all lower-case in the witnessing string**, `bone_` prefix, **snake_case**, underscore-separated.
  (Casing is evidentially void — the hash folds every byte with `|0x20`.)
* `<feature>` is a **descriptive English anatomical noun**: eyeball, eyelid, eyebrow, brow, cheek, nose,
  mouth, jaw, tongue.
* `<position>` is an **optional** middle qualifier: top, bottom, corner, center, tip.
* `<side>` **trails** and is a full word: left, right, center. **No `l`/`r` abbreviation is ever used on a
  facial bone** (unlike the body rig's `bone_lhand`/`bone_rhand`). Side is always the *last* token.

### Worked examples (all confirmed, all regenerated by the config in §3 at expected-false 0.000)

| String | feature | position | side |
|---|---|---|---|
| `bone_jaw` | jaw | — | — |
| `bone_nose_left` | nose | — | left |
| `bone_cheek_right` | cheek | — | right |
| `bone_brow_center` | brow | — | center |
| `bone_eyebrow_center` | eyebrow | — | center |
| `bone_eyelid_top_left` | eyelid | top | left |
| `bone_mouth_corner_left` | mouth | corner | left |
| `bone_mouth_bottom_right` | mouth | bottom | right |
| `bone_tongue_tip` | tongue | tip | — |

### Contrast with the body rig (do NOT mix grammars)

The *body* uses `Bone_<Part>` CamelCase with **glued** `L`/`R` (`Bone_LForearm`, `bone_rshoulder`,
`bone_lthumb1`). The *face* uses `bone_<feature>_<side>` with **spelled-out trailing** side. `Bone_Head`
(track 24) is the boundary: it is a body-grammar bone; everything below it that FaceFX drives switches to
the facial grammar. **This boundary matters for the unknowns** — the 8 targets sit right on it, and could
belong to *either* dialect (see §5).

## 2. Vocabulary — confirmed, and (emphasis) what is plausibly MISSING

The negative result already banked (`bone_census.md` §4c): the full obvious facial vocabulary
(eye/eyelid/eyebrow/brow/cheek/nose/mouth/lip/jaw/chin/tongue/teeth/ear/temple/forehead/sneer × top/bottom/
corner/center/tip/mid/upper/lower/inner/outer × left/right/center) returns **zero** on these 8. So the
answer is a term we *don't* have, or a structure we haven't tried. This section enumerates both, checked
against the sibling **Saboteur** `FaceFX/Male.fxa` rig (a full CamelCase facial bone list — different
spelling, same anatomy, strong corroboration for *what facial bones exist*).

### 2a. Confirmed Mercs2 features (20 bones)

`eyeball`, `eyelid`(top only), `eyebrow`(l/r/center), `brow`(center), `cheek`, `nose`, `mouth`(top/bottom/
corner), `jaw`, `tongue`(tip only).

### 2b. Features we hold ONE variant of — the sibling proves there are more

| We have | Saboteur shows also exists | Plausible MISSING Mercs2 string |
|---|---|---|
| `bone_eyelid_top_*` | `Bone_LowLid_*`, `Bone_UnderEye_*`, `Bone_EyeBlink_*` | `bone_eyelid_bottom_*`, `bone_eyelid_lower_*`, `bone_lowlid_*`, `bone_undereye_*` |
| `bone_tongue_tip` | `Bone_Tongue_Mid` | `bone_tongue_mid`, `bone_tongue_base`, `bone_tongue_back`, `bone_tongue_root`, `bone_tongue_middle` |
| `bone_mouth_top/bottom/corner_*` | `Bone_UpperLip_*`, `Bone_LowerLip_*`, `Bone_InnerUpperLip_*`, `Bone_InnerLowLip_*`, `Bone_OuterUpperLip_*`, `Bone_LipCorner_*` | `bone_mouth_upper_*`, `bone_mouth_lower_*`, `bone_lip_upper_*`, `bone_lip_lower_*`, `bone_lip_inner_*`, `bone_lip_outer_*` |
| `bone_cheek_*` | `Bone_LowerCheek_*` | `bone_cheek_lower_*`, `bone_cheek_bottom_*`, `bone_cheek_puff_*` |
| `bone_eyebrow_*`, `bone_brow_center` | `Bone_OutBrow_*` (outer brow) | `bone_eyebrow_outer_*`, `bone_brow_outer_*`, `bone_brow_left/right` |
| `bone_eyeball_*` | `Bone_Eye_*` | (eyeball confirmed; no extra) |

### 2c. Whole features Mercs2 might have that we have NOT witnessed at all

From the Saboteur list + standard 2008 FaceFX rigs, features entirely absent from our confirmed set:

* **Structural / control bases** — `Bone_HeadBase`, `Bone_MouthBase`, `Bone_JawBone` in Saboteur.
  Mercs2 analogues would be **glued or `_base`/`_root` suffixed** control bones: `bone_headbase`,
  `bone_mouthbase`, `bone_jawbase`, `bone_facebase`, `bone_face`, `bone_facial`, `bone_facefx`,
  `bone_mouth_base`, `bone_jaw_base`, `bone_face_root`, `bone_mask`. **This is the strongest lead for the
  jaw-parent (track 26) and the under-head bone (track 25)** — see §5.
* **teeth** — `Bone_teeth_top` / `Bone_teeth_bottom` (Saboteur, note lower-case `teeth` even in its
  CamelCase file → Mercs2 `bone_teeth_top`, `bone_teeth_bottom`; possibly `bone_teeth`, `bone_teeth_upper`,
  `bone_teeth_lower`).
* **sneer / nasolabial** — `Bone_Sneer` (single, midline) → `bone_sneer`, `bone_sneer_left/right`,
  `bone_nostril_*`, `bone_philtrum`.
* **chin / jowl / dimple** — not in Saboteur but standard → `bone_chin`, `bone_chin_left/right`,
  `bone_jowl_*`, `bone_dimple_*`.
* **Head accessory / attach bones** (a *different* family — Mercs2 has a rich `bone_attach_*` + prop-bone
  set: `bone_cigar`, `bone_camera`, `hp_fx_cigar`, `bone_necklace`, `bone_hair`). A head-region bone that
  FaceFX does **not** drive could be one of these, not an anatomy bone at all: `bone_attach_head`,
  `bone_attach_face`, `bone_cigar`, `bone_hat`, `bone_glasses`, `bone_headset`, `hp_head`.

### 2d. What the Saboteur rig told us (and its limits)

* **Corroboration:** teeth (top+bottom), a distinct **MouthBase / HeadBase / JawBone** control layer, a
  **Tongue_Mid** (so tongue is multi-segment, not just tip), lower-lid / under-eye / eye-blink eye bones,
  and inner/outer/upper/lower **lip** bones. Every one of these is a *real facial-bone concept* a Pandemic
  2008 rig ships — so the missing-vocabulary in §2b/§2c is grounded, not invented.
* **Limit:** Saboteur's grammar is CamelCase (`Bone_JawBone`, `Bone_Sneer`, `Bone_Tongue_Mid`) and does
  **not** hash-match Mercs2 (verified: `m2("Bone_JawBone") ≠ 0xEB221048`, etc.). The two games **share the
  body rig but not the face rig** — different rigger, different spelling. So Saboteur supplies the *concept
  checklist*, never the literal Mercs2 string. It cannot crack a hash; it can only tell us which anatomy to
  spell in Mercs2's own dialect.

## 3. `bone_forge`-ready ARRAYS + SLOT_ORDERS

Two calibrated blocks. **Block A** is the anatomy generator (regenerates all 20 confirmed facial bones —
positive control passed, expected-false 0.000). **Block B** targets the control/structural + accessory
hypotheses for the specific unknowns. Both are stored as ready configs:
`docs/reverse_engineer/facefx_forge_anatomy.json` and `..._structural.json` (mirror the JSON below).

### Block A — facial anatomy (the confirmed dialect, extended with §2 missing terms)

```json
{
  "arrays": {
    "prefix": ["bone"],
    "feature": [
      "mouth","jaw","lip","lips","chin","tongue","teeth","tooth","gum","gums",
      "cheek","face","head","mask","nose","nostril","sneer","jowl","dimple",
      "philtrum","brow","eyebrow","eyelid","lid","socket","eye","eyeball",
      "temple","forehead","muzzle","throat"
    ],
    "mod": [
      "","base","top","bottom","upper","lower","inner","outer","mid","middle",
      "back","front","corner","center","tip","root","blink","puff","under","over"
    ],
    "side": ["","left","right","center","c"]
  },
  "slot_orders": [
    ["prefix","feature","mod","side"],
    ["prefix","feature","side","mod"],
    ["prefix","mod","feature","side"],
    ["prefix","feature","mod"],
    ["prefix","feature"]
  ]
}
```

Grammar note: side is a **trailing full word**; keep `l`/`r` OUT of the facial `side` array (they never
appear on a facial bone). The `mod` `""` entry makes the qualifier optional; the auto-underscore enumerator
covers glued vs separated so both `bone_mouthbase` and `bone_mouth_base` are generated.

### Block B — structural / control / accessory bones (for tracks 25, 26, 28–33)

```json

    "mod": ["","base","root","top","bottom","upper","lower","front","back","mid","aim","end","01","02","a","b","1","2"],
    "side": ["","left","right","l","r"]
  },
  "slot_orders": [
    ["prefix","feature","mod","side"],
    ["prefix","feature","side","mod"],
    ["prefix","mod","feature","side"],
    ["prefix","feature","mod"],
    ["prefix","feature"]
  ],
  "templates": [
    "bone_facefx","bone_facial","bone_faceroot","bone_facebase","bone_mouthbase",
    "bone_jawbase","bone_headbase","bone_maskbase","bone_headnub","bone_headend",
    "bone_tonguebase","bone_tonguemid","bone_tongueback","bone_tongueroot",

```

## 4. Test results (this session)

| Config | raw expansions | expected-false | hits on the 8 |
|---|---|---:|---:|
| Block A (anatomy + all §2 missing terms) | 237,688 | 0.000 | **0** |
| Block B (control + accessory + body-grammar) | 366,401 | 0.001 | **0** |
| **Positive control** (Block A vs 5 *confirmed* facial hashes) | 237,688 | 0.000 | **5/5 regenerated** |

The positive control is the load-bearing evidence: the identical vocabulary that reproduces `bone_jaw`,
`bone_cheek_left`, `bone_mouth_corner_left`, `bone_nose_left`, `bone_mouth_bottom_left` exactly, at
expected-false 0.000, produces **nothing** for the 8 targets. The harness works and the dialect is
correctly modelled — therefore the 8 names are genuinely **outside** the anatomy-in-facefx-grammar space.
This corroborates the pre-existing brute-force negative (`bone_census.md` §4c: ~500 M candidates,
enrichment-vs-control null, exhaustive ≤13-char sweep) rather than re-deriving it.

**No hit is claimed.** A mirror pair 28/31 landing together would have been strong; it did not happen.

## 5. The 8 targets — reasoned candidate families (HYPOTHESES ONLY)

Anatomical pinning from the reference clip:
```

26  0xEB221048   PARENT of bone_jaw
27 bone_jaw

30  0xFE747044   jaw region                          │

32  0xFBFA3B2C   jaw region
33  0xA3EEDAF2   jaw region
34 bone_mouth_bottom_left …
```
**Critical constraint (from `bone_census.md` §4b):** these 8 are **NOT present in the FaceFX actor**. The
20 confirmed facial bones ARE the FaceFX-driven expression deformers; these 8 are ride-along / structural /
accessory bones that FaceFX does not pose. That rules OUT the obvious expression vocabulary and points at
**base/control bones, rigid ride-alongs (teeth/tongue), or head accessories.**

### Track 26 — the jaw's parent — HIGHEST-CONFIDENCE FAMILY: a mouth/jaw base

The single best-reasoned target. In the Saboteur rig the jaw hangs off **`Bone_MouthBase`**; a
head→(base)→jaw chain is textbook FaceFX. Candidate family, in dialect:
`bone_mouthbase` · `bone_mouth_base` · `bone_jawbase` · `bone_jaw_base` · `bone_mouth` (bare) ·
`bone_mouth_root` · `bone_facebase` · `bone_face_base`. All tested (Block A/B) — none hit, so if it is one
of these the spelling differs (e.g. a studio-internal token) or it exceeds the generator's slots.

### Track 25 — under Head, above 26 — a head/face base

Head → **25** → 26(jaw-parent) → jaw is a two-link chain. 25 is the upper control. Family:
`bone_headbase` · `bone_head_base` · `bone_face` · `bone_facebase` · `bone_facefx` · `bone_facial` ·
`bone_head1`-style continuation (note `bone_head1`..`bone_head4` already exist as named accessory bones!) ·
or an **accessory** bone (`bone_attach_head`, `bone_cigar`, `bone_hat`). The existing `bone_head1..head4`
family is a real, witnessed Mercs2 pattern and a live alternative to an anatomy interpretation.

### Tracks 28–33 — six jaw-children, with 28/31 a +X/-X mirror pair

Because they are jaw *children* and NOT FaceFX-driven, the leading interpretation is **rigid oral structure
that rides the jaw**: teeth and tongue segments, plus one left/right pair.

* **Midline single bones (fits 29, 30, 32, 33):** `bone_teeth_top`, `bone_teeth_bottom` (Saboteur has both),
  `bone_tongue_base`, `bone_tongue_mid`, `bone_tongue_back`, `bone_tongue_root` (Saboteur has `Tongue_Mid`;
  we already have `bone_tongue_tip` far below at track 36, so a base/mid near the jaw is anatomically sound).
* **The mirror pair 28 (+X) / 31 (−X):** a left/right jaw-region bone that FaceFX doesn't drive. Best
  families: **jaw hinge/condyle** (`bone_jaw_left`/`bone_jaw_right`, `bone_condyle_left/right`,
  `bone_jaw_hinge_left/right`), **lower-cheek/masseter** (`bone_cheek_lower_left/right`), or **a masking/
  physics helper** (`bone_jaw_l`/`bone_jaw_r`). Note the facial dialect otherwise forbids `l`/`r` — but
  these are non-FaceFX bones and *might* follow the body dialect instead (glued `l`/`r`), which is exactly
  why the pair is worth spelling both ways.

### Structural caveat on 28–33

An equally live reading: 28–33 are the **non-expression control skeleton** of the mouth (a base + L/R
corners + upper/lower pivots) that the FaceFX morphs *drive into*, authored as plain rig bones. That would
make the mirror pair `bone_mouth_left`/`bone_mouth_right` or `bone_lip_left`/`bone_lip_right` (bare, no
position) — also tested, also null.

### Honest status

All families above were generated and tested; **all returned zero at expected-false ≤ 0.001.** Combined
with the exhaustive brute-force negative, the conclusion of `bone_census.md` stands: these 8 are either
built from **studio-internal vocabulary no dictionary holds**, or spelled **>13 characters**, and the only
decisive route is an **unstripped dev/debug build** of Mercs2. This artifact narrows the *search* (control-
base bones for 25/26; teeth/tongue + one L/R pair for 28–33) and supplies the grammar to recognise a hit if
such a build surfaces — it does not claim a crack.
