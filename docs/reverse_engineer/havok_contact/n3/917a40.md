# FUN_00917A40 (pc-v10): which of 4 old + 1 new contact points to drop

Image: `game-files/canonical/dumps/mercs2_unpacked.exe`, sha256 `8c179a99…c7ba` (cmp.txt), equal to the corpus pc-v10
image. Body 0x917A40..0x918576 (Ghidra size 2871 = 0xB37; `int3` padding from 0x918577). Listing: `d_917a40.s`
(objdump Intel, this folder). The bytes 0x917A40..0x918580 are identical in `n2/mercs2_n2patched2.exe`, so there are no
SecuROM splices (cmp.txt, PROVEN). The function has no calls (PROVEN, writes.txt has no `call`).

Grades: **P** = PROVEN from the listing/bytes this run; **I** = INFERRED; **S** = SPECULATIVE; **ND** = not determined.

## 0. Port conventions

- `f32(x)`: rounding to binary32. It happens at every `fst/fstp dword`. A `fld dword` is an exact widening.
- Every other value is an x87 register value. It is written as an f64 op (53-bit precision control, per the port rule).
- `K_*` constants are given as the exact f64 the instruction loads (§4).
- `a <. b` means the compare holds only when ordered and strictly less. NaN never takes the update/continue path.
  Every compare in this function is one of these strict, ordered predicates; there is no `<=`.
- Compare decoding (fnstsw; C0 = ah 0x01, C2 = 0x04, C3 = 0x40):
  - `test ah,0x05; jp skip` skips unless `lt`.
  - `test ah,0x41; jne skip` skips unless `gt`.
  - Operand order: `fcom/fcomp/fcompp` compare st0 against the operand (or st1).
- The tracer `n2/gsk/x87sym.py` agrees with the hand trace on every range run (`t_A.txt`, `t_p2.txt`, `t_cross0.txt`,
  `t_fin1..3.txt`).
- Raw encodings of register-form ops (`divbytes.txt`):
  - `fdivp st(1),st` = `DE F9`, so st1 = st1 / st0.
  - `fsubp st(2),st` = `DE EA`, so st2 = st2 − st0.
  - `fsubrp st(i),st` = `DE E0+i`, so st(i) = st0 − st(i).
  - These are the SDM encodings (recalled) and are consistent with N2's `fsubdiv_summary.txt` (P/I).

## 1. Inputs (P)

- **ECX is the only input.** Evidence:
  - EBX, EDX and ESI are zeroed at 917A50/917A5D/917A65 before any read. EDI is set at 917C6E.
  - EBP is only the frame (917A41).
  - There are no `[ebp+…]` reads and no stack-argument reads (ebx.txt, writes.txt).
- `pt(i) = ECX + 0x30*i`, for i = 0..4. Only these fields are read:
  - `+0x0, +0x4, +0x8`: position x, y, z (f32).
  - `+0x1C`: "dist" (f32). This is the 4th float of the second vec4.
  - +0xC, the normal xyz (+0x10..+0x18) and the id at +0x20 are **never read** by 917A40.
- Stride 0x30 is P: the code reads offsets 0, 0x30, 0x60, 0x90, 0xC0 and computes `lea r,[i+2i]; shl r,4`.
- Index 4 (ECX+0xC0..+0xDC) is treated as the new point. That role is I, from the caller (§5).
- 917A40 reads **no manifold bytes**: no nA/nB/np and no 8-byte point entries. The layout facts in the task are the
  caller's business, see §5.

## 2. Frame (P, by hand; the tracer's `S±` names after `and esp,-0x10` are not used)

Let A = esp after `sub esp,0x64` (917A46). The pushes happen at 917A4B (ebx), 917A58 (esi) and 917A69 (edi).

- `fst [esp+8]` at 917A4C has esp = A−4, so the slot is A+4.
- `fstp [esp+0x10]` at 917A59 has esp = A−8, so the slot is A+8.
- From 917A69 on, esp = A−12, so `[esp+X]` = A+X−12. Both slots above are therefore `[esp+0x10]` = **BEST** (running
  max) and `[esp+0x14]` = **MIN**.

Slots, named by the `[esp+X]` they have from 917A69 on:

| slot | name |
|---|---|
| `[10]` | BEST |
| `[14]` | MIN, the f32 nearest squared distance from the new point |
| `[18]` | scratch d, later RATIO |
| `[1C]` | DD = f32(new.dist − pt(iMin).dist), later scratch |
| `[20..28]`, `[30..38]` | f32 component scratch |
| `[4C],[50],[54],[58]` | D[0..3] = f32 squared distance new↔pt(i) (phase 1) |
| `[5C..6C]` | `flag[0..4]` (5 × u32, zeroed at 917A6A–917A84; the decomp's `[8]` is wrong) |

After phase 1, `[14]` and `[4C..58]` are never written again. `[1C]` is not written between 917C7A and 918426
(writes.txt).

**x87 leftovers that carry values (P):**
- Z = 0.0 from `fldz` at 917A49 is never popped by its `fst`. It is st1 at 917AC0. It stays at the stack bottom through
  phases 1–2 and is popped into BEST at 917EAB.
- Z2 = 0.0 from `fldz` at 9181D4 is the comparand at 918232 (st1). It is replaced by DD at 9183EB.
- Phase 3 j=0 reaches 8 registers at 917EFD. That is only legal because Z was consumed, which confirms the bookkeeping.

## 3. Pseudocode, in the binary's order

```
// sq3(a,b): the squared distance, used everywhere below
//   dx=f32(a.x-b.x); dy=f32(a.y-b.y); dz=f32(a.z-b.z)
//   return f32( ((f64)dx*dx + (f64)dy*dy) + (f64)dz*dz )
// The association is ((x²+y²)+z²) (fmulp/fxch/faddp at 917AA8–917AB6). The decomp's (z²+x²)+y² is wrong.
// Operand order of each difference is given per call site as a,b.

flag[0..4] = 0
BEST = f32(0.0)                       // 917A4C; the register Z = 0.0 stays on the stack
MIN  = f32 @0xBEAB40                  // 917A59
iMax = 0 (edx), iMin = 0 (esi)

// ---- phase 1: distances from the new point (917A5F–917C5C) ----
D[0] = sq3(pt4, pt0)                  // new − old
if D[0] >. 0.0 : BEST = D[0]          // 917AC0 fcom st1 (=Z); test 41 / jne
if D[0] <. K_MAXF64 : MIN = D[0]      // 917ACD fcom qword 0xB58BF8; test 5 / jp. iMin = 0 either way
for i in 1,2,3:                       // unrolled at 917AE4, 917B5F, 917BDA
    D[i] = sq3(pt4, pt(i))
    if BEST <. D[i] : BEST = D[i]; iMax = i       // fld BEST; fcomp st1; test 5 / jp
    if MIN  >. D[i] : MIN  = D[i]; iMin = i       // fld MIN;  fcomp st1; test 41 / jne
// The strict compares make the FIRST index win ties. NaN never updates.

DD = f32( pt4.dist - pt(iMin).dist )  // 917C5E–917C7A: fld [ecx+0xDC]; fsub [iMin*0x30+ecx+0x1C]
flag[iMax] = 1
P  = pt(iMax)
BEST = f32( BEST * K_105 )            // 917C81–917C94: fmul qword 0xB5A3F0
// ---- phase 2: the point farthest from P (917C98–917E7A) ----
i2 = 4                                // lea esi,[edi+3] at 917C91
for j in 0..3: if flag[j]==0:
    d = sq3(P, pt(j))                 // P − pt(j)
    if BEST <. d : BEST = d; i2 = j   // fcomp; test 5 / jp; fstp BEST
if flag[4]==0:                        // always true here
    d = sq3(P, pt4)                   // P − new
    if BEST <. d : i2 = 4             // fcompp at 917E6E; BEST NOT stored
flag[i2] = 1                          // 917E89

// ---- phase 3: the largest |v × e| (917E7C–9181D2) ----
ex=f32(P.x-pt(i2).x); ey=f32(P.y-pt(i2).y); ez=f32(P.z-pt(i2).z)   // 917E7C–917EA7; kept as registers
BEST = f32(Z) = 0.0                   // 917EAB, pops Z
i3 = 0                                // xor edi,edi at 917E8D
for j in 0..4: if flag[j]==0:         // blocks at 917EC1, 917F58, 917FF5, 918092, 918138
    vx=f32(pt(j).x-P.x); vy=f32(pt(j).y-P.y); vz=f32(pt(j).z-P.z)   // pt(j) − P
    cx = f32( (f64)vy*ez - (f64)vz*ey )
    cy = f32( (f64)vz*ex - (f64)ez*vx )
    cz = f32( (f64)vx*ey - (f64)vy*ex )
    a  = f32( ((f64)cx*cx + (f64)cy*cy) + (f64)cz*cz )
    j==0   : if a >. 0.0  : BEST = a          // fldz; fcom st1; test 41 / jne (917F35–917F46); i3 stays 0
    j=1..3 : if BEST <. a : BEST = a; i3 = j  // fcomp; test 5 / jp
    j==4   : if BEST <. a : i3 = 4            // fcompp 9181BE; BEST not stored
// Every product is exact in f64 (24×24 bits); each difference rounds to f64, then to f32.
// The j=4 schedule (918162–918192) differs and the hand trace gives the same three formulas.
// cy's products come in the order vz*ex − ez*vx (P, t_cross0 t10/t11, hand trace).
flag[i3] = 1                          // 9181E0

// ---- phase 4: the point farthest from pt(i3) (9181D4–9183D1) ----
BEST = f32(0.0)                       // fldz; fst. The register Z2 = 0.0 stays
Q = pt(i3); i4 = 0                    // xor esi,esi 9181E8
for j in 0..4: if flag[j]==0:
    d = sq3(Q, pt(j))                 // Q − pt(j)
    j==0   : if d >. 0.0  : BEST = d               // fcom st1 (=Z2) at 918232; test 41 / jne
    j=1..3 : if BEST <. d : BEST = d; i4 = j
    j==4   : if BEST <. d : i4 = 4                 // fcompp 9183C3
flag[i4] = 1                          // 9183D1

// ---- decision (9183D9–918558) ----
if flag[4] != 0: goto SCAN                          // 9183DD: the new point is among the kept four
if !(DD <. 0.0): goto SCAN                          // 9183E7 fcom st1 (=Z2); test 5 / jp
if !(MIN <. (DD * (DD * K_526))): goto SCAN         // 9183F6–91840B: t1 = DD*K_526 (f64 const), t2 = DD*t1; fcompp
// ratio search over the 4 old points; flags are NOT consulted
RATIO = f32 @0xB5A3E0; r = 4                         // 918411–91841C
nd = f32(pt4.dist)                                   // 918420; kept as a register for the whole loop
for i in 0..3:                                       // unrolled at 91842A, 918480, 9184CB, 918516
    q   = f32( pt(i).dist - nd )                     // old − new (i=0 fsubp st2; i=1,2 fsub st,st(2); i=3 fsubrp st2)
    q2  = f32( (f64)q*q )
    den = f32( q2 + K_EPS )                          // i=0..2 stored at [10], i=3 at [1C]
    lhs = (i==0) ? K_RATIO64 * D[0]                  // 91845F fld qword 0xB5A3D0; fmul st,st(1)
                 : (f64)RATIO * D[i]                 // i=1,2 fmulp; i=3 fmul dword [58]
    if lhs <. den:                                   // fcomp/fcompp; test 5 / jp
        r = i
        if i < 3: RATIO = f32( den / (D[i] + K_EPS) ) // fadd st,st(2) (=eps); fdivp st(1),st = den/(D+eps)
        // i==3: no division and no store
return r                                             // 918550

SCAN (918559/91855B):                                // 918559 pops the leftover register (Z2 or DD)
for e in 0..4: if flag[e]==0: return e               // first unflagged, ascending
return 0                                             // 91856E
```

**Default and collision behaviour (P, from the code):**
- The defaults are i2 = 4, i3 = 0 and i4 = 0.
- When geometry is degenerate (every candidate ≤ 0 or NaN), i3 or i4 can stay at an index that is already flagged.
  Fewer than 4 distinct flags then get set.
- SCAN returns the lowest unflagged index. That can be < 4 even when flag[4] is 0.
- Port SCAN literally. Do not replace it with "return 4".

**Decision paths:**
- The ratio path runs only when all of these hold:
  - the new point is not among the kept four;
  - it is deeper than its nearest old point (DD < 0);
  - 526·DD² > MIN.
- The ratio path returns the old point i that maximises (Δdist² + eps)/(D_i + eps). That ratio must beat
  K ≈ 0.0304617, and then beat each earlier winner, through the eps-free test `RATIO·D_i < den`.
- If no old point beats it, the ratio path returns 4.
- The meaning of the heuristic is I. That K = (10°)² in rad² is S: 0.0304617 ≈ (π/18)², a numeric coincidence check
  only.

## 5. Caller FUN_00918580, at the call (P unless marked)

- Entry is `sub esp,8` followed by pushes of ebx, ebp, esi, edi. That puts esp at entry−0x18 at 91859D.
- `mov ecx,[esp+0x38]` therefore loads entry+0x20 = **arg8** (1-based; arg1 = entry+4). That arg is N2 §5.4's
  "prevFirst". This is the only input, as `call 0x917A40` at 9185A1 shows.
- The return value goes to ebp. If ebp == 4, the caller returns 5 (9185A8–9185B9).
- The manifold is `esi = arg1` (918586):
  - `cmp byte [esi+2],4` is the gate (91858A).
  - `movzx ecx, word [esi+8*k+6]` is the u16 id passed to `mgr->vtbl[0x14]` (9185C1–9185D3).
  - The 8-byte entries live at `[esi+8*k+4]`.
  - For k ≠ 0, the caller copies entry[0] over entry[k]. For k == 0, it copies entry[1] (`[esi+0xC]`,`[esi+0x10]`) over
    entry[0] (9185D5–9185F3).
  - These facts are P for 918580's use. "agentData+0xC" is ND here: it is not visible in either function.
- After a successful add, `ecx = arg8 + k*0x30` and `push arg7` lead to `call 0x90BE70` (9186A4–9186A9), and
  `[arg7+0x20] = id` (91869A).
  - So arg8 is the stride-0x30 point array and arg7 is the new point (I: 90BE70 is a copy from arg7 into slot k).
- That arg7 == arg8+0xC0, the slot 917A40 reads as the new point, is **I/ND**: no write ties them in these two
  functions.
