# Penetration-depth subtree under 0x9118d0: FUN_00941e10 and its callees (pc-v10)

Scope: FUN_00941e10 and everything it calls. 0x9118d0 itself, the GSK core and its other callees are
the parent's. Binary: the restored copy `n2/mercs2_n2patched2.exe`. Grades: **PROVEN** means read
this run from bytes, a listing, or a mechanical trace, with the source cited. **INFERRED** means
reasoned from those, or recalled. **SPECULATIVE** means a guess.

## 0. Method and artefacts (all in `gsk/pd/` unless noted)

- Function bodies and call lists come from Ghidra headless with `-noanalysis`, using `scripts/GskDecomp.java`.
  - Run 1, depth 6, root 0x941e10: project `pd/gproj` (pd1), output `pd/out/_functions.tsv`.
  - Run 2: `pd/out2/_functions.tsv`. It adds 0x940980 and 0x940e40, which Ghidra misses because
    only 0x940f50's switch cases call them.
- `f_<va>.s`: objdump listings (`--no-show-raw-insn --x86-asm-syntax=intel`) of every body range.
  0x940f50 is dumped whole in `f_940f50_full.s`, 0x940f50–0x941c34, because Ghidra's body for it
  omits the switch cases.
- `gsk/tr/pd_<va>.txt`: SSA traces made by `pd/x87sym_pd.py`.
  - The tracer is two-pass. It versions stores as `[addr]@storeVA`, invalidates register-keyed
    memory on register writes, decodes `fcom`/`fnstsw`/`test ah`/`jcc` into the outcomes
    {lt, eq, gt, un} that take the jump, and models `--pop` for callee-cleaned arguments.
  - Jobs are in `pd/jobs_pd.txt`, generated by `pd/mkjobs.py`.
  - The traces are the arithmetic source of truth for operand order. Where two paths join, the
    tracer keeps the stack of whichever path it reached last, so read joins against the listing.
- Constants are read with `gsk/peread.py`, which maps through the PE section table. Their outputs
  are in `consts*.txt`, `tbl_*.txt` and `strings.txt`.
- Imports are resolved by walking the PE import directory with `pd/imports.py`.

## 1. Mechanical checks

- **SecuROM splices** (PROVEN, `pd/splice_membership.txt`; `pd/splice_940f50.txt` covers
  0x940f50–0x941c4f).
  - No site in `pc-v10.splices.tsv` falls inside any body range of the 29 closure ranges.
  - No site falls in the 0x940f50 switch body.
  - No part of this subtree depends on an unrestored splice.
- **x87 vs SSE** (PROVEN, `pd/sse_grep.txt`, grep of `xmm|movss|mulps|cvt|fldcw|fnstcw|fninit|fild|fist`).
  - Every function is x87 except FUN_0041bc80, which is scalar SSE (`movss/mulss/addss/xorps`, so
    every operation rounds to f32).
  - The only integer-to-float conversion is `fild` at 0x9407c7.
  - The subtree contains no `fldcw` or `fnstcw`.
- **Imports** (PROVEN, `pd/import_b0511c.txt`, `pd/import_b053ac.txt`).
  - IAT slot `[0xb0511c]` is KERNEL32 `TlsGetValue`.
  - 0x9ee730 is `jmp [0xb053ac]`, which is MSVCR80 `_CIsqrt`.
- **Monitor timers.** 0x941e10 brackets its work with Havok monitor-stream records (PROVEN, `pd/strings.txt`).
  - Mechanism: `TlsGetValue([0xdfe754]=0x17)`, then, if `[s+4] < [s+0xc]`, it writes a 12-byte
    record {string ptr, rdtsc low} at `[s+4]`.
  - The start record uses string 0xb5aa48 "TtPenetration"; the end record uses 0xbce914 "Et".
  - Arithmetic effect: none. A port can omit this. That omission is a decision for the caller, not
    a fallback.
- **0x9ee850** (PROVEN, `f_9ee850.s`) is the MSVC `_alloca_probe` page-touch loop with 0x1000
  steps. 0x941c50 uses it for its 0x2ec4-byte frame.

## 3. Data layouts

**ctx**: built on 0x941e10's stack. Code reads it through ecx = esi in callees. PROVEN from the
`t_941e10.txt` store offsets.

| off | content |

| +0x40..0x4c | eps, replicated ×4 |

| +0x5c | attempt counter, = 0 |

The A, Braw and M arrays use a 16-byte stride (PROVEN, 0x940980).

**Vertex record (vrec)**, 0x40 bytes in the polytope (PROVEN: 0x940820 stores, decomps of 0x9423c0 and 0x940980):
- +0x00 M = A − T(B)
- +0x10 support point of A (A space)
- +0x20 support point of B (raw, B space)
- +0x30 int flag, zeroed by callers at 0x941ccc and 0x941d18 and by 0x944040.

**Polytope (poly)**: a local at 0x941c50 `esp+0x20` (PROVEN offsets; capacities INFERRED from the checks).
- +0x08 vertex count, initialised to 4 by 0x9423c0. 0x941c50 stops at 55 (`cmp ebx,0x37; jge`, 0x941cf4).
- +0x0c: set to 0 by 0x9423c0.
- +0x10: face count, set to 4 by 0x943a10.
- +0x20: vrec[i] at +0x20+0x40·i.
- +0xf70: face[j] at +0xf70+0x50·j.
- The face budget test is in 0x9409f0 (§6).

**Face**, 0x50 bytes (PROVEN for 0x9434e0, 0x943a10, 0x9426a0, 0x944040):
- +0x00 unit normal n, 4 floats; w = scale × 0.0.
- +0x10, +0x20, +0x30: three half-edge records of 16 bytes each, {vrec*, next*, twin*, face*}.
  The initialisation is table-driven from 0xb5aaa0 (36 dwords, `pd/tbl_b5aaa0.txt`).
- +0x40: plane distance d = n·v0, the key that 0x9426a0 minimises.
- +0x44: int flag.

## 6. Leaves called by the driver

**FUN_00940820**: Minkowski support (PROVEN, `f_940820.s`, `tr/pd_940820.txt`).
- `v+0x10 = shapeA.support(dir)`.
- The B-space direction is `dB = Rᵀ(−dir)`, using ctx columns 0–2, with `dB.w = 0`. Per component
  the order is `((c.x·(−dx) + c.y·(−dy)) + c.z·(−dz))`; see the trace for the exact association.
- `v+0x20 = shapeB.support(dB)`.
- `pB = R·v20 + t` (ctx).
- `v.xyz = f32(v10 − pB)`.
- `v.w = f32(v10.w − f64 0.0)` (0x940962: `fsub qword [0xbea968]`, which is +0.0).

**FUN_00940980** (PROVEN, decomp plus listing): appends one vrec to the GJK arrays.
- `M[count]=v+0`, `A[count]=v+0x10`, `B[count]=v+0x20`.
- Then `count++`.

**FUN_00940e40(dir, ref, vrec, &dist)** (INFERRED role).
- It takes the support in `dir` and the support in `−dir` (two calls to 0x940820), projects each
  relative to `ref`, and keeps one.
- The comparison at 0x940f12 branches if `d_new > d_old` or unordered.
- It copies 13 dwords (0x42c800) on one path.
- Exact selection logic: `tr/pd_940e40.txt`.

**FUN_00940f50**: the initial-simplex repair/grow state machine on ctx.count, jump table 0x941c34.
PROVEN control flow from `tr/pd_940f50_full.txt`.

The cases are entered with x87 stack = {0.0} (`fldz` at 0x940f70). `ebx` starts at −1 and records
the highest level already grown from, which prevents oscillation.

Case 4 (0x940f79):
- `e1=f32(p0−p1)`, `e2=f32(p1−p2)`, `n=e1×e2` (f32 per component), `n.w=0`.
- `d=f32((p3−p0)·n)`.
- If `f32(f32(|n|²)·eps2) < d·d` (d·d held in a register, unrounded), or the compare is unordered:
  `res=0`, **return 0** (0x941c06). This is the polytope-ready exit.
- Otherwise, if `ebx>=3`: `res=3`, return 1. Otherwise `count=3` and fall into case 3.

Case 3 (0x9410cc):
- Same `n` from p0, p1, p2.
- If `f32(|n|²) != 0` (`fucomp`, taken on lt/gt/un), go to 0x941766: set `ebx=3`, normalise `n`
  (0 if |n|²==0, else `1/f32(sqrt)`), then grow with 0x940e40 and 0x940980, then go to case 4.
- If the triangle is degenerate and `ebx>=2`, take 0x9418ec, an exit with a constructed answer:
  - `out.dist=0`.
  - `e=p0−p1`. Take the axis of largest |e|, using strict/non-strict comparisons as in the trace.
  - `out.n` = the perpendicular `{.., e_j, .., −e_i}`, normalised by `1/sqrt`, or scale 0.
  - `L=f32((|p0.y|+|p0.x|)+|p0.z|)`.
  - `t=f32(L/((L+L)+f64 1.1920929e-07))`.
  - `out.pt = f32(t·A[1] + (1−t)·A[0])` per lane, `(1−t)` as `f32(1.0−t)`.
  - `res=0`, return 1.
  - Note that L is built only from p0; both operands of `L+L` come from the same slot (0x941a6d–0x941a79).
- Otherwise `count=2` and fall into case 2.

Case 2 (0x9411cb):
- If `eps2 < f32(|p0−p1|²)`, or unordered, go to 0x9414dd: grow from the segment (0x940e40 and
  related), then go to case 3.
- Otherwise, if `ebx>=1`: `res=3`, return 1. Otherwise `count=1`.

Case 1 (0x941247):
- If `eps2 < f32(|p0|²)`, or unordered, go to 0x94137e (`ebx=1`):
  - Take two supports: one along the direction stored at S+0x130, one along `−p0`.
  - Compare `f32(|sA−p0|²)` with `f32(|sB−p0|²)`. If the second is greater, or the compare is
    unordered, add the second (0x9414c7); otherwise add the first.
  - Then go to case 2.
- Otherwise, if `ebx>=0`: `res=3`, return 1 (0x941c1c). Otherwise `count=0`.

Case 0 (0x94128b):
- `dir = −ctx.T.t` (4 lanes).
- If `eps2 >= f32(|t|²)`, `dir = (0,1,0,0)` from .data 0xbf65b0 (file value; .data is writable).
- Call 0x940820 then 0x940980.
- If `eps2 >= f32(|p0|²)` (eq/gt): separated exit 0x94183e:
  - `out.dist = f32(sqrt(f32(|p0|²)))`, `out.n = dir`, `out.pt = local vrec+0x10`.
  - `res=0`, return 1.
- Otherwise `ebx=0` and go to case 1.

Other exit:
- 0x941ae5, from the case-3 growth when `eps.x > dist`, i.e. `[esi+0x40] > [S-0x19c]`:
  - `out.dist=0`; `out.n` = the normalised plane normal.
  - Call `FUN_9223c0(…, M0, M1+0x10, M2+0x20 …)`. The pointer arithmetic follows the listing at
    0x941b0d–0x941b1e.
  - `out.pt = Σ bary·A` (order in the trace at 0x941b29–0x941bdb).
  - `res=0`, return 1.

**FUN_009423c0 / FUN_00943a10 / FUN_009434e0**: polytope construction (PROVEN layout; operand
order in the traces).
- 0x9423c0 copies 4 vrecs and sets the flags to 0, then calls 0x943a10.
- 0x943a10 wires 4 faces from table 0xb5aaa0, then computes face 0's plane.
- If `f32(n·(v0−v1)) > 0.0` (`[0xb11ad0]` = 0.0f; branch at 0x943af2), it swaps the vrec
  pointers to re-orient the faces.
- It then recomputes the planes for faces 3, 2, 1 and 0.
- 0x9434e0, the face plane:
  - `n = (v0−v1)×(v1−v2)`.
  - `s = (|n|²==0) ? 0 : 1/f32(_CIsqrt(|n|²))`.
  - `n *= s`; `n.w = s·0.0`.
  - `d = (v0·n)` with the association from the decomp: `(v0.y·n.y + v0.x·n.x) + v0.z·n.z`.
    That association is INFERRED; verify it against `tr/pd_9434e0.txt`.

**FUN_009426a0** (PROVEN, `tr/pd_9426a0.txt`): returns the face with minimum d.
- The scan starts with face 0 as the best.
- A face replaces the current best only if `best > cand` strictly. A tie or NaN keeps the earlier
  face, so the first minimum wins.
- The scan is unrolled ×4 plus a remainder loop, and checks no flag. INFERRED: removed faces are
  excluded by giving them d = FLT_MAX, since `[0xbeab40]` = 3.40282e38f is loaded at 0x942657
  and 0x943705.

**FUN_009409f0**: one EPA expansion step (PROVEN, `f_9409f0.s` 0x940a8e–0x940bae).
- `w_i = f32(v.M − face.v_i.M)` for i = 0..2 (4 lanes).
- `dist = 41bc80(w, face.n)`, SSE: `dist_i = f32(f32(f32(w_i.z·n.z) + f32(w_i.y·n.y)) + f32(w_i.x·n.x))`;
  `dist_3 = 0`.
- Lane bits: bit 8 = `dist0 < eps.x`, 4 = `dist1 < eps.y`, 2 = `dist2 < eps.z`, 1 = `0 < eps.w`.
  All are strict and ordered (`test ah,0x41; je/jne`).
- If `bits & 0xe`: `res=0`, return 1. That is converged.
- `rc = poly.FUN_942630(face, v, &cnt, &list)`. If `rc != 0`: `res=3`, return 1.
- If `(poly[+0xc] − poly[+0x10]) + 100 < cnt`: `res=2`, return 1. This is the face budget.
- If `poly.FUN_943730(cnt, list, v) != 0`: `res=3`, return 1.
- Otherwise return 0.

**FUN_00940bc0**: extraction (PROVEN, `tr/pd_940bc0.txt`).
- Up to 10 iterations (`cmp ebx,0xa; jl`):
  - Copy the face's three M into `ctx.M[0..2]`.
  - Call `FUN_9223c0(P=&0xb132f0 (0,0,0,0), M0, M1, M2, bary)`.
  - Accept if `!(b0<0) && !(b1<0) && (b2>=0 || NaN)`. The b0 and b1 tests branch only when
    `0 > b` (ordered).
  - Otherwise `face = FUN_943b30(face)`.
- Copy the face's A and Braw into `ctx.A/ctx.B[0..2]`; `ctx.count=3`.
- `out.pt[l] = f32(f32(f32(A0[l]·b0) + A1[l]·b1) + A2[l]·b2)` for l = 0..3.
- `out.dist = −face.d`; `out.n = −face.n` (4 lanes).

**FUN_009223c0**: barycentrics of P projected on triangle (a, b, c) (INFERRED from the decomp
structure; the arithmetic is in `tr/pd_9223c0.txt`).
- With `u=a−b` and `v=c−b`, take the Gram determinant `D = |v|²|u|² − (u·v)²`.
- If `0 < D`: closed-form barycentrics, scaled by `1/D`.
- Otherwise fall back to the longest edge: one coordinate is 0 and the other two are
  `t, 1−t`, or all zero.
- The return layout is `out[0..2]`.

## 7. Horizon and new-face routines (roles INFERRED; arithmetic and branch outcomes PROVEN in the traces)

- **0x942630(face, v, &cnt, &list)**: loads `[0xb5aa30]` = 1e-7f and `[0xbeab40]` = FLT_MAX.
  It calls 0x942570; on 1 it calls 0x943660. It is the visibility seed for the horizon walk.
- **0x942570**: a visibility test of v against a face with tolerance `f64[0xb5aa08]` = 1.0000000117e-07.
  Branches: 0x9425d0 eq/gt/un, 0x9425db lt/eq/un, 0x9425f0 eq/gt/un, 0x942616 lt/eq.
- **0x943660**: a recursive depth-first walk over the twin edges (it calls itself at 0x9436bb).
  It tests return codes 1, 2, 3 and 4 and writes face flags at +0x44.
- **0x943730(cnt, list, v)**: builds the cone of new faces.
  - A plane with `|n|² == 0` (`fucom`, je 0x9439f5) returns failure, which leads to res=3.
  - Otherwise it normalises with `1/sqrt`.
  - Finally it clears the flags of `poly.nf` faces and `poly.nv` vrecs.
- **0x943b30(face)**: picks the next face for 0x940bc0 after calling 0x944040 (flag reset). It uses
  `f64[0xb5ab30]` = −9.99999949e-11 and `f64[0xb59c18]` = 0.89999998, and visits at most 3
  neighbours (`cmp edi,3`).
- **0x944040**: zeroes `face+0x44` for `poly.nf` faces and `vrec+0x30` for `poly.nv` vrecs.

- **0x944090** evaluates one direction:
  - It takes `shapeA.support(−d)` and `shapeB.support(Rᵀd)`.
  - It computes `val = d·(…)` with the transform from aTb.
  - It replaces best if `best.val < val`, strictly (0x944206 skips on eq/gt/un).
  - That role is INFERRED. The x87 stack depth was 6 at the calls at 0x9446f5–0x94473a, so values
    are held in registers across the calls.
- The loop count 3 comes from the decomp's `4.2039e-45` (int bits 3). It is INFERRED and not
  checked against the listing.

## 10. NOT DETERMINED

1. **Translation w lane in the perturbation.** 0x941db6 adds `[esp+0x1c]`, a stack slot that
   0x941c50 never writes, to `ctx.T.t.w`. Its runtime content is not determinable statically.
   I checked every store in `f_941c50.s`. Whether any consumer reads `T.t.w` was not checked.
2. **x87 precision-control word** (shared with the parent). It sets the rounding of every
   register-held intermediate tN. Nothing in this subtree sets it (grep of `fldcw`: none).
3. **Full operand order** of 0x9423c0's follow-up 0x9434e0, the 0x940f50 growth paths
   (0x9414dd–0x941761, 0x941766–0x941839), and 0x940e40, 0x942570, 0x943660, 0x943730,
   0x943b30, 0x944090 and 0x944270.
   - Their mechanical SSA traces exist in `gsk/tr/pd_*.txt`.
   - I did not review them line by line into pseudocode. The roles given above are INFERRED.
   - The 0x944270 trace has a stack-depth mismatch at the back-edge join 0x94432e. The trace at
     0x94432a–0x944340 must be read from the listing (`f_944270.s` lines 57–68).
4. **Exact meaning of 0x943b30's neighbour choice** and of the 0x943660 return codes 1–4.
5. **Behaviour of `fld` on w-lane vertex-id bit patterns that are NaN or denormal.** `fsub 0.0`
   at 0x940962 and the f32 copies all pass through x87, so a signalling-NaN pattern would be

6. **Runtime contents** of the .data constants at 0xbf65a0..0xbf65dc. Only the file values were read.
